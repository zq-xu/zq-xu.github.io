# Token 节约规则（全局）

## 1. 直接落盘，拒绝对话框预印
- 严禁在对话里打印整篇新文档、整份文件或大段修改后的代码全文。
- 确认目标路径后，直接用 `write_to_file`（新建/整文件）或 `replace_in_file`（局部替换，search/replace 块）一次性写入。
- 禁止 “Here is the document...”“以下是为您生成的...” 等前导词与格式解释。写完只回 1 句话：文件路径 + 核心变更点。

## 2. 最小化读取与回读
- 先用 `search_codebase` / grep 定位行号，再按行范围读取；能读 50 行就不读 500 行，绝不整篇读大文件只为找一个片段。
- 不回读刚写入的文件做全文校验；校验只用 grep/head 等命令检查关键点，输出截断到 50 行以内。
- 不把命令的大段输出贴进对话，只回报结论。

## 3. 模式与模型分工
- **Plan 模式**：只做极简大纲与步骤（≤300 token），严禁在 Plan 模式下修改文件。复杂架构设计、全库扫描类任务用 `mimo-v2.6-pro`。
- **Act 模式**：方案确认后的常规修改用 `mimo-v2.6-flash`，通过精密的局部替换一次完成落地，避免“整文件重写→再修”的多轮往返。

## 4. 长内容先确认大纲
- 预估生成内容超过 2,000 字：先在 Plan 模式输出 Markdown 列表大纲（目录级，不含正文），待用户确认后再切 Act 模式一次性写入文件。
