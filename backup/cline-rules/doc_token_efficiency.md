# Token 节约规则（全局）
 
## 1. 直接落盘，拒绝对话框预印
- 严禁在对话里打印整篇新文档、整份文件或大段修改后的代码全文。
- 确认目标路径后，直接用 `replace_in_file`（局部替换）或 `write_to_file`（新建/整文件）一次性写入，禁止“先在聊天框贴全文、再复制落盘”。
- 禁止“Here is the document...”“以下是为您生成的...”等前导词与格式解释。
- 代码任务写入后仅回复 1 句话：文件路径 + 核心变更点。
- 文档类任务（新建或修改 `.md` 等文档）写入后，只回复文件路径和修改的章节标题，例如“已更新 `docs/x.md`：新增『读取预算』、修改『输出截取』”。不得在聊天框重复文档正文，也不得用项目符号逐条复述修改内容。
 
## 2. 最小化读取与输出
- 先用 `search_files` 或 grep 命令定位关键行号，按需读取关联上下文；严禁无目的整篇读取无关的大文件。
- 单个任务整文件读取不超过 3 次，超出时先说明理由。
- 写入后不做全文回读。如需确认关键内容，仅用 grep 检查关键行，命令输出控制在 50 行以内。若工具返回匹配失败或报错，必须先重新读取相关片段，再继续处理。
- 测试、构建、基准的输出只保留失败用例或最后 50 行，不把巨量输出直接塞进对话。
 
## 3. Plan / Act 分工（VS Code 手动切换时遵循）
- **Plan 模式 = 只读调研与方案**：仅输出极简大纲与步骤（≤300 token），严禁修改、写入任何文件；复杂架构设计、全库扫描类任务配合 `mimo-v2.6-pro` 使用。
- **Act 模式 = 只写执行**：收到明确指令后直接调用工具落盘，不再复述方案或在聊天框预印；常规修改配合 `mimo-v2.6-flash` 使用，通过精密的局部替换一次完成，避免多轮往返。
- **切换约定**：Plan 方案经用户确认后 → 切 Act 执行；Act 中发现方案需要大改 → 回 Plan 澄清，不在 Act 中即兴大规模重构。
 
## 4. 大任务防御（防止 Act 模式滥用 Token）
- Act 模式下涉及 **≥3 个文件**、或**预估改动/生成超过 2,000 字**的重构/新建需求：先用 1-2 句话提示用户“该任务改动较大，建议切至 Plan 模式先梳理架构，是否仍直接在此执行？”，得到确认后再执行。
- 文档类新增/重写超过 2,000 字：先在 Plan 模式输出目录级大纲（不含正文），用户确认后再切 Act 模式一次性写入文件。
- **特例**：用户已明确“直接落盘 / 不用大纲 / 直接执行”，或已在 Prompt 中提供完整清单（如目录结构、文件列表）时，视为已确认，直接执行，无需追问。
 
## 5. 任务边界
- 完成一个任务后，用 5 行以内总结当前状态（已改内容、未完成事项），并提示用户开新任务。
